# 开发注意事项

- Windows 文件名不区分大小写，组件交互检查不得仅用首字母大小写与 SQL 逻辑检查区分。例如使用 TableDesignerComponent.test.ts 与 tableDesigner.test.ts，避免覆盖已有文件。

- 可拖动预览窗口使用 transform，会改变子元素 position:fixed 的包含块。共享下拉不能直接把视口坐标写入该包含块，必须扣除变换祖先的原点；新增弹窗应同时检查键盘选择和可见列表位置，不能只验证输入回填。

- 主窗口关闭不能在 WindowClosing 通知中直接 Quit：那时草稿还没获得确认。使用可取消钩子先阻止关闭，再异步通知前端，批准后的退出只执行一次；不能在关闭钩子里同步等待 WebView。

- 查询投影中的 CURRENT_DATE / CURRENT_USER / NULL 等无括号表达式不能按物理字段处理，即使表里恰有同名字段。保守解析须区分关键字和反引号标识符；不确定时原样只读执行。

- 多表 DDL 失败不等于所有目标均未变更：不要保留旧列表并直接重试整个旧选择。无论成功、服务器错误或响应不确定，均刷新核对；删除仅使用已确认的表名快照，不跟随随后变化的筛选/选中项。

- PowerShell 中配置 OleDbConnectionStringBuilder 使用标准完整键名（如 Data Source），不要依赖带别名的动态属性访问，否则 ACE 可能报“找不到可安装的 ISAM”。连接参数不能拼进进程参数或日志。
- 本环境中，Windows PowerShell 的 ADOX 新库创建出现过原生驱动异常；不要将 ACE/ADOX 放在 Go 主进程中直接激活。导出复制本项目生成的空白 Access 容器，在有期限的隔离系统进程中写入并回读，失败不发布文件。
- ACE 的 Excel 枚举可能同时返回命名范围和带 $ 的工作表，带空格的名称可能带外层单引号；仅列实际工作表并规范化外层引用。驱动可能重写导出工作表名，必须限制可用名称并核对结果，不能静默改名或保存有损结果。

- 主包通过 go:embed 嵌入 frontend/dist。Vite 构建会清空该目录，不能同时运行主包 go test/go build；先完成前端构建或整包发布，再顺序运行主包检查，否则可能出现嵌入资源暂时缺失的假失败。

- package.ps1 的构建阶段会执行 npm ci，重建 frontend/node_modules；不要同时运行 Vitest 等前端检查，避免依赖删除期间出现 MODULE_NOT_FOUND 的假失败。先完成打包，再运行前端检查。

- 移除导出总量限制不能仅删除前端 LIMIT：SQL 预览、文件导入和旧批量写入接口各有独立边界。导出须走单独的后端流式通道；系统驱动回读也必须逐行校验，不能重新将整表载入内存。dBASE 会将字段名转成大写，DBF 字段核对按格式规则忽略大小写，其它格式仍精确核对。

- 引擎类型切换只在用户选择控件的 change 事件中重置默认值，不通过监听原生子窗口收到的新 model 重置配置，避免服务端回填覆盖保存的端口、服务名和凭据。已保存类型固定，旧标签页不能被换到另一种协议。MongoDB 命令首字段有语义，预览使用有序 bson.D；JSON map 排序可能把 filter 放到 find 前，导致错误命令。

- SQL Server 的 NewConnectorConfig 不会补齐零值 msdsn.Config 的传输协议。先用结构化 URL 经 msdsn.Parse 初始化 TCP/协议参数，再覆盖验证 TLS 配置；使用本地非数据库 TCP 端点验证真实驱动已拨号并干净失败，不能只用编译通过证明连接初始化正确。
